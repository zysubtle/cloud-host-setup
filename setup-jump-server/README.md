# 新跳板机与 Claude Code 服务器：交互配置

适用：**两台全新的 Ubuntu 24.04 云主机，IPv4**。建议在同一地域、同一 VPC 中，使用私网连接；脚本也支持跳板通过固定公网出口连接服务器。

文件：

- `setup_jump.sh`：在跳板机执行，安装 Mosh、配置设备公钥、生成独立的服务器访问密钥，设置 SSH 别名。
- `setup_server.sh`：在业务服务器执行，安装 SSH、tmux、Git，授权跳板公钥。不安装 Claude Code。

两个脚本均独立可用，不依赖另一个文件放在本机。它们通过可复制的单行连接信息交换**公钥、地址和验证标识**，不交换私钥。

## 先准备

1. 在云控制台确认两台机器的角色，记录各自公网/私网 IP。通过私网连接时，需要已互通的 VPC/路由。Mac 若经加速线路连接跳板，另记下加速线路的公网 IP；线路需原样（端口号不变）转发跳板的 SSH 端口（TCP）和 UDP 60000–61000。
2. 确认业务服务器上要用的普通账号已安装好 Claude Code，脚本不安装也不检查它。保留业务服务器的互联网出口，供软件安装和 Claude Code 使用。仅有私网 IP 时，需要 NAT 等出站通道；不要为了限制入站 SSH 删除唯一公网出口。
3. 在两台机器分别打开一个 **root 或可 sudo 的交互终端**。业务服务器的初始配置优先用云控制台 VNC/交互终端；如果要避免 Mac 的公网 IP 出现在业务服务器的 SSH 来源中，初始配置和上传阶段也不要从 Mac 直接 SSH/SCP 到业务服务器。非交互的“发送命令”不能回答脚本提问。
4. 把 `setup_jump.sh` 放在跳板机，`setup_server.sh` 放在业务服务器。脚本默认不授予新建普通账号 sudo，之后仍使用原 root/可 sudo 终端完成配置。收紧后 SSH 只允许脚本里选定的普通账号登录，建议选用已有、可 sudo 的账号（如 `ecs-user`）；若该账号没有可用的 sudo，收紧前脚本会提示，默认不继续。
5. 在 Mac 准备一把 SSH 公钥。查看：`cat ~/.ssh/id_ed25519.pub`。若尚无此文件，可执行 `ssh-keygen -t ed25519`，遇到已有文件时不要覆盖。脚本只接收 `.pub` 的一整行文本。iPhone 可另用终端 App 生成的公钥，脚本支持追加多把设备公钥。

假设文件在 Mac 的“下载”目录，且已经能用 SSH 登录跳板，可用下面命令传输跳板脚本（替换大写占位符；未建立 SSH 登录时，用云控制台上传）。业务服务器脚本用云控制台的文件上传功能放到对应机器：

```bash
scp ~/Downloads/setup_jump.sh LOGIN_USER@JUMP_PUBLIC_IP:~/
```

## 执行顺序

**1. 在跳板机运行：**

```bash
sudo bash ~/setup_jump.sh
```

如果当前是 root，也可以直接 `bash ~/setup_jump.sh`。按提问填写：跳板普通账号、Mac 连接跳板用的公网 IP（直连填跳板 EIP，走加速线路填加速 IP；脚本会从阿里云实例元数据读出本机 EIP 作为默认值）、Mac 公钥、业务服务器地址/账号/现有 SSH 端口和 SSH 别名。连接方式按服务器地址自动判断：填私网地址走私网，填公网地址走公网。

两个脚本启动时都会先检查本机是否已有 UFW 自定义规则、非本脚本创建的 sshd 配置片段或遗留的收紧备份，发现即停止，避免两端流程走完后才发现无法收紧。

脚本会显示配置预览。确认后安装/授权，并列出云安全组需放行的规则。

接着打印一条单行的 **Mac 验证命令**。在 Mac 新开终端执行整行（bash、zsh、fish 均可）：它先把跳板的主机公钥写入 Mac 的 `~/.ssh/known_hosts`（已有相同条目则跳过），再严格按这把公钥登录，所以首次连接不需要手动确认指纹；跳板终端也会显示主机指纹供核对。如本地私钥不是默认文件，在 `ssh` 后补充 `-i 私钥路径`；私钥设有口令时按提示输入即可。Mac 显示 `PAIR_OK` 后回到跳板按回车。跳板会显示它看到的来源 IP；走加速线路时，这是线路的回源地址而不是 Mac 的 IP，属于正常现象。

Mac 上若报错：`Permission denied (publickey)` 多为公钥/私钥不匹配；超时或 `Connection refused` 多为跳板安全组、加速线路转发或网络；`Host key verification failed` 表示对方主机公钥不符，应先确认连接的是这台跳板；报错指向 `known_hosts` 文件本身时，先修正该文件的权限。

这一步在联系服务器之前进行。如果发现 Mac 公钥贴错，此时输入 `:quit` 并执行 `--reset` 重填，只需重来跳板这一端。

验证通过后，脚本输出以 **`JUMP1:`** 开头的一整行连接信息，然后停下来等待服务器返回信息。复制整行，保留这个终端。

**2. 在业务服务器运行：**

```bash
sudo bash ~/setup_server.sh
```

粘贴 `JUMP1:` 开头的整行信息。脚本会显示目标账号、跳板来源和公钥指纹，请核对是否是正确的机器后确认。

脚本完成安装和授权后，输出以 **`SERVER1:`** 开头的一整行返回信息，并等待跳板登录测试。复制整行，保留这个终端。

**3. 回到跳板机终端：**

粘贴 `SERVER1:` 信息，确认它来自正确服务器的可信控制台。脚本写入指定的服务器主机公钥，不会关闭 SSH 指纹检查，然后自动尝试登录服务器。

登录失败或超时时，脚本显示 SSH 的错误输出；修正云安全组、VPC/路由或公钥配置后按回车重试，脚本不会在此时关闭原入口。如果是跳板端填写的服务器地址或端口有误，输入 `:quit` 退出，按下文“重新填写”执行 `--reset`。

**4. 回到业务服务器终端：**

跳板显示测试通过后，在服务器终端按回车。服务器检查由这次跳板 SSH 登录产生的验证结果，然后显示即将应用的 SSH 和 UFW 设置。确认后自动收紧：

- SSH 只允许选定普通账号从指定跳板来源使用公钥登录；关闭 root SSH、密码和键盘交互认证。
- 系统 UFW 只放行该跳板来源访问服务器的 SSH 端口，其他入站默认拒绝，出站允许。
- tmux、Claude Code 在该普通账号下运行。

确认前，若该账号没有可用的 sudo，脚本会额外提示收紧后只能经云控制台管理，默认不继续。收紧完成后，服务器在该账号的 `~/.local/state/paired-access/` 下写入“已收紧”标记，供跳板复核。

**5. 回到跳板机终端完成：**

服务器显示完成后，回到跳板按回车。脚本再次登录服务器，确认收紧后跳板仍能连上，并检查服务器写入的“已收紧”标记。如果能连上但没有标记（服务器仍在等待回车，或收紧失败已自动恢复），脚本会提示先查看服务器终端，处理后重试，不会显示完成。如果服务器刚收紧后跳板连不上，在服务器控制台执行 `sudo bash setup_server.sh --rollback` 恢复，查明原因（如安全组、跳板出口 IP）后再重跑服务器脚本。

复核通过后，脚本显示跳板收紧预览（选定账号没有可用 sudo 时同样会提示），确认后自动启用仅密钥登录和 UFW，允许跳板的 SSH 与 Mosh UDP 端口，支持 Mac/iPhone 切换网络。Mac 能以公钥登录已在第 1 步确认。

## 云安全组如何填写

云安全组属于云平台配置，**这两份脚本不调用阿里云 API**。脚本会输出实际 IP 和端口，按下面对应关系在控制台设置。系统 UFW 与云安全组都必须允许对应流量。

| 机器 | 入方向协议/端口 | 来源 |
| --- | --- | --- |
| 跳板 | TCP，现有 SSH 端口，通常 22 | `0.0.0.0/0`，配合已验证的密钥登录，便于切换网络 |
| 跳板 | UDP `60000/61000` | `0.0.0.0/0` |
| 业务服务器 | TCP，现有 SSH 端口，通常 22 | 脚本输出的跳板实际来源 IPv4 `/32` |

私网模式填跳板私网 IP；公网模式填业务服务器实际看到的跳板 EIP/NAT 出口。不要把 Mac 公网 IP 或加速线路 IP 填到业务服务器的 SSH 来源：加速线路只用于 Mac → 跳板，跳板 → 服务器不经过它。

走加速线路时，进入跳板的流量来自线路的回源地址，跳板两条规则的来源 `0.0.0.0/0` 已经涵盖。若想把来源收窄到线路的回源地址段，就不能再从别处直连跳板，回源地址变化时也要同步修改。

先新增精确允许规则，验证跳板可用后再收紧原有宽泛规则。**仅新增 `/32` 规则，仍保留原有 `0.0.0.0/0` 允许规则，不能达到限制来源的目的。**检查实例关联的所有安全组。

业务服务器不需要为此方案开放 Mosh UDP。两端出站需可用，业务服务器访问 Claude Code 服务的公网出口保持可用。购买实例、VPC、交换机、公网 IP、云安全组和云账号登录不在脚本自动配置范围内。

## 日常使用

跳板脚本完成后会打印包含实际地址、用户名、端口和别名的 Mac 登录命令。它会用 Mosh 登录跳板，再通过 SSH 打开业务服务器上的 `tmux` 会话 `claude`。命令里的地址就是你填的 Mac 连接地址（走加速线路时为加速 IP）。如临时改为直连跳板 EIP，Mac 会把它当作另一台主机，首次连接要求确认主机指纹，对照脚本显示的跳板指纹即可。

Mac 若未安装 Mosh：

```bash
brew install mosh
```

业务服务器会话中进入项目目录，然后运行：

```bash
claude
```

脚本不安装 Claude Code，按业务账号已安装处理。首次账号登录需要你本人在官方 CLI 流程完成；脚本不会索取账号密码、API Key 或登录令牌。

需要暂时离开 tmux 时，先按 `Ctrl+B`，松开后按 `D`。下次使用脚本输出的命令可回到同一 tmux 会话。脚本完成的 SSH 测试不等于从 Mac 实测了 Mosh UDP；第一次使用应实际运行这条 Mosh 命令。

## 重跑、恢复与限制

- 直接重跑同一脚本会读取本机配置记录，复用专用私钥；不会重新生成已有密钥、重复叠加授权或同名 SSH 配置段。跳板专用私钥不设口令，以便自动连接服务器，权限为 `600`，只保存在跳板账号的 `.ssh` 中。
- 本机状态保存在 `/var/lib/paired-ssh-setup/jump/` 或 `/var/lib/paired-ssh-setup/server/`，仅 root 可读。连接信息与后续说明也会保存于相应目录。
- `--status` 查看记录，`--help` 查看参数。记录表示脚本执行进度，不代替对后来手工改动的检查。
- **重新填写：**填写有误（如 Mac 公钥、服务器地址、账号）时，在**尚未收紧**的机器上执行 `sudo bash setup_jump.sh --reset` 或 `sudo bash setup_server.sh --reset`。需要交互确认（默认否）；本机记录改名保留为 `state.json.reset-时间戳`，下次运行重新提问。已安装的软件、账号和专用密钥保留，本脚本写入的公钥和 SSH 配置段在重新配置时替换。跳板重置后会生成新的 `JUMP1:` 信息；如果服务器已粘贴过旧信息，服务器也要先 `--reset`。已经收紧的机器需先 `--rollback`。
- **以后新增设备公钥**（如换了新 iPhone）：直接追加到跳板账号的 `~/.ssh/authorized_keys`，写在 `# BEGIN paired-access-v1` 到 `# END paired-access-v1` 这一段之外。段内由脚本管理，重跑时会被重写；段外的公钥会保留。
- 配置文件内容发生变化时保留 `.bak.时间戳` 备份。若已有非本脚本创建的同名 SSH 别名、sshd 配置片段或 UFW 自定义规则，脚本会停止，保留原配置；其中 sshd、UFW 和遗留收紧备份在脚本启动时就检查。适用于全新实例，不用于直接接管已有业务服务器。
- 命令执行失败时，脚本会一并显示该命令的错误输出（例如已有 `~/.ssh/config` 的语法错误），便于定位。
- SSH/UFW 收紧发生错误时会尝试恢复；如果会话中断，重新运行会提示恢复。也可在原云控制台 root/可 sudo 终端执行：

```bash
# 在对应机器执行对应脚本
sudo bash setup_jump.sh --rollback
sudo bash setup_server.sh --rollback
```

`--rollback` 只恢复本脚本收紧前的本机 sshd 和 UFW 设置，**不回滚云安全组、删除账号、公钥、项目或卸载软件**。它不需要交互确认，SSH 无法登录时也可通过云助手等“发送命令”方式以 root 执行（脚本文件需仍在该机器上）。

回滚后本机记录标为未完成；服务器回滚还会删除“已收紧”标记。服务器回滚后重跑时，如果已有跳板这次登录留下的验证结果，不再打印 `SERVER1:` 信息、也不等待跳板，直接进入收紧预览。跳板回滚后重跑时，如果此前已确认服务器收紧，会跳过 Mac 验证和服务器端步骤，直接复核服务器后重新收紧跳板。

如果最初网络不通导致 apt 安装失败，修复互联网/DNS/软件源后重跑。安装步骤不升级整机系统。两端脚本不改变 SSH 监听端口，避免干扰 Ubuntu 24.04 的 SSH socket activation。

脚本限定 IPv4。新实例使用新私钥，不把旧跳板的私钥复制过去。后续换 IP、换目标机器或增加服务器，需重新核对地址、授权和云安全组；需要重新填写时用 `--rollback`（如已收紧）加 `--reset`，不应直接篡改脚本的 root 状态文件。这套配置控制指定路径的 SSH 来源，不消除云平台控制台的访问记录。
