# Syncthing 私网双向同步（Ubuntu，同 VPC 的两台服务器）

用 [Syncthing](https://syncthing.net/) 在两台**同一 VPC** 的 **Ubuntu** 服务器之间，通过**私网**双向同步一个文件夹。安装、配置、首次同步、切换为双向，都由一个脚本完成。IP、目录等信息在运行时交互输入。

两台服务器分别叫 A 和 B：

- **A**：数据来源。要同步的文件夹已经在 A 上。
- **B**：接收方。先完整接收 A 的数据，再切换为双向。之后在 A 或 B 上的修改都会同步到另一台。

```
A：发送与接收 ─────────────── 私网 TCP 22000 ─────────────── B：仅接收 ──首次同步完成──> 发送与接收
```

> **同步只走私网。** Syncthing 只监听本机私网 IP，关闭了全局发现、本地发现、中继和 NAT 穿透，对方的地址固定为对方的私网 IP。两台之间只需要互通 **TCP 22000**，不需要对公网开放任何端口。安装时需要从 GitHub 下载 Syncthing，访问不了的话可以离线安装。

---

## 命令

| 命令 | 在哪台运行 | 作用 |
|---|---|---|
| `sudo bash syncthing-vpc-sync.sh` | A、B | 交互式安装和配置（等同于 `setup`）。可以重复运行，用来修改配置或更改同步目录 |
| `sudo bash syncthing-vpc-sync.sh finalize` | 只在 B | 等首次同步完成，再把 B 切换为双向。用于 setup 结束时没有切换，或者中途退出的情况 |
| `sudo bash syncthing-vpc-sync.sh status` | A、B | 查看连接和同步状态 |
| `bash syncthing-vpc-sync.sh help` | — | 显示用法 |

- 以 root 登录时可以省略 `sudo`。
- **请用 `bash` 运行。** Ubuntu 的 `sh` 是 dash，用 `sh` 运行会提示并退出。
- `setup` 和 `finalize` 需要在交互式终端里运行。

## 准备

### 1. 系统要求

- Ubuntu 20.04 及以上版本（如 22.04、24.04），x86_64 或 ARM64。不是 Ubuntu 时，脚本会直接退出。
- 有 root 权限。
- 缺少 `curl`、`jq`、`tar` 时，脚本会用 apt 自动安装。Ubuntu 默认没有装 `jq`。
- 能访问 GitHub，用来下载 Syncthing。访问不了的话，见下文"离线安装"。

### 2. 安全组放行 TCP 22000

- **两台在同一个普通安全组里**：组内默认私网互通，不用改（除非你把组内策略改成了"组内隔离"）。
- **不在同一个安全组，或者用的是企业级安全组**：在两台各自的安全组里，各加一条入方向规则：

| 授权策略 | 协议类型 | 端口范围 | 授权对象 |
|---|---|---|---|
| 允许 | 自定义 TCP | 22000/22000 | 对方的私网 IP，例如 `172.16.0.11/32` |

系统防火墙：Ubuntu 默认没有启用 ufw。如果启用了，脚本会自动放行 22000 端口，而且只对对方 IP 放行。如果用的是自己写的 iptables 或 nftables 规则，需要手动放行。

### 3. 把脚本上传到两台服务器

把整个 `syncthing-vpc-sync` 目录上传到两台服务器，放在哪里都可以：

```bash
# 在你自己的电脑上执行
scp -r syncthing-vpc-sync root@<A 的公网 IP>:/root/

# B 没有公网 IP 的话，可以在 A 上通过私网传过去
scp -r /root/syncthing-vpc-sync root@<B 的私网 IP>:/root/
```

## 快速开始

> **建议在 B 上用 tmux 或 screen 运行**，例如先执行 `tmux new -s sync`，断线后用 `tmux attach -t sync` 回来。B 的首次同步在数据多时要很久，这样 SSH 断开也不会中断脚本。
>
> 不用 tmux 也可以。脚本退出或 SSH 断开都不影响后台同步，之后运行 `finalize` 继续即可。

在 A、B 上都运行脚本。两边要同时开着（开两个终端窗口，分别登录 A 和 B），因为中途要把各自的设备 ID 输入到对方的窗口里：

```bash
cd /root/syncthing-vpc-sync
sudo bash syncthing-vpc-sync.sh
```

### 第 1 步：回答问题

两台分别回答，**一台选 A，另一台选 B**。下面是 A 上的例子。方括号里是默认值，直接回车就使用默认值：

```
本机角色：
  1) A —— 数据来源（已有要同步的文件夹）
  2) B —— 接收方（先完整接收 A 的数据，再切换为双向同步）
请选择 1 或 2: 1
本机（A）私网 IP [172.16.0.10]:
对端（B）私网 IP: 172.16.0.11
运行 Syncthing 的系统用户（需要对同步目录有读写权限） [root]:
本机要同步的目录（绝对路径；A、B 上的路径可以不同）: /data/share
文件夹 ID（A、B 必须填写相同的值） [share]:
被删除/覆盖的旧文件在 .stversions 中保留几天（0 表示不启用版本控制） [30]:
设置 Web 管理界面密码（直接回车则不设置/不修改）:
```

每一项的含义见下文"各项输入说明"。答完后会显示一份汇总，确认后开始安装。

### 第 2 步：互相输入设备 ID

安装完成后，每台都会显示自己的设备 ID，然后等待输入对方的设备 ID：

```
================================================================================
  本机（A，172.16.0.10）的设备 ID：

    XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX

  1. 把上面这个 ID 输入到 B 上运行的脚本中；
  2. 把 B 上的脚本显示的设备 ID 输入到下面。
================================================================================
B（172.16.0.11）的设备 ID:
```

把 A 显示的 ID 粘贴到 B 的窗口，把 B 显示的 ID 粘贴到 A 的窗口。粘贴时多了空格、或者变成了小写都没关系。如果复制不完整或者有错字，脚本会提示重新输入。

### 第 3 步：等待连接

两台会添加对方、共享文件夹、重启 Syncthing，然后等待连接，最多等 90 秒。看到类似下面这行，就说明连上了：

```
[完成] 已连接到 B（172.16.0.11:22000），双方都已共享文件夹 share
```

先输完 ID 的那台，可能会因为另一台还没输完而提示"90 秒内未能连接"。这没关系，Syncthing 会自动重连。等另一台也完成后，用 `status` 确认即可。

A 上的脚本到这里就结束了。

### 第 4 步：B 等待首次同步，然后切换为双向

B 会接着询问：

```
现在等待首次同步完成，并自动把 B 切换为双向？ [Y/n]
```

直接回车。脚本每 10 秒刷新一次进度，同步完成后自动切换，最后显示：

```
[完成] B 已切换为“发送与接收”，A 与 B 现在是双向同步（A 之后的变化也会继续同步过来）
```

**切换完成之前，不要在 B 上修改同步目录里的文件。** A 可以照常使用，A 上的新修改会继续同步到 B。

### 第 5 步：检查状态

在任意一台运行下面的命令。输出的含义见下文"查看状态"。

```bash
sudo bash syncthing-vpc-sync.sh status
```

## 各项输入说明

| 问题 | 默认值 | 说明 |
|---|---|---|
| 本机角色 | — | `1` 是 A（已有数据的一方），`2` 是 B（接收方） |
| 本机私网 IP | 自动检测 | 必须是本机网卡上的 IP |
| 对端私网 IP | — | 对方的私网 IP |
| 运行 Syncthing 的系统用户 | 执行 `sudo` 的用户；直接用 root 登录时是 root | 必须能读写整个同步目录，家目录必须可写（Syncthing 的配置存在家目录里）。可以用 root，但更建议用实际使用这些文件的用户，两台保持一致 |
| 本机要同步的目录 | — | 绝对路径，A、B 上可以不同。A 上必须已存在；B 上不存在时会自动创建。不能是系统目录（`/`、`/usr`、`/etc`、`/boot` 等），也不能是运行用户的家目录或它的上级目录 |
| 文件夹 ID | `share` | **A、B 必须相同**。只能包含字母、数字、`.`、`_`、`-`。改为同步另一个目录时，要换一个新的 ID，见下文"更改同步目录" |
| 旧文件保留天数 | `30` | 被删除或覆盖的旧文件在 `.stversions` 里保留几天。`0` 表示不启用。见下文"旧版本文件" |
| Web 管理界面密码 | 不设置 | 要输入两次。直接回车表示不设置；重新运行时直接回车表示不修改。服务器上还有其他登录用户时，建议设置 |
| Web 管理界面用户名 | `admin` | 只有设置了密码才会问 |

遇到下面这些情况，脚本会额外确认：

| 情况 | 默认 | 说明 |
|---|---|---|
| A 上的目录是空的 | 否 | 提醒你确认没有把 A、B 选反 |
| B 上的目录不是空的 | 否 | 这些文件在切换为双向前需要处理，见下文"B 上已有文件或改过文件" |
| 目录里有不属于运行用户的文件 | 否 | 询问是否执行 `chown -R`。选否时：如果运行用户连目录本身都不能读写，脚本退出；否则继续，没有权限的文件会同步失败 |
| 之前用另一个用户运行的 Syncthing 还在运行 | 是 | 询问是否停掉旧的服务，避免两个 Syncthing 争用 22000 端口和同一个目录 |

重新运行时，上次填写的值会作为默认值（密码除外）。

## 首次同步与切换为双向

### 为什么分两步

B 先设为"仅接收"，只从 A 拉取数据，B 上的改动不会发给 A。这样在首次同步期间，A 的数据不会受到 B 的影响。B 拉取完成后，再改为"发送与接收"。

### 什么时候算同步完成

同时满足下面几个条件时，脚本认为首次同步已完成：

- 已连接 A，并且 A 已经共享了这个文件夹。
- B 上文件夹的状态为空闲（idle），没有待同步的文件，也没有错误。
- 在连续 3 次检查（约 30 秒）中，A 的索引没有新的变化。

等待期间会显示一行进度：

```
连接A:true  A端共享:valid  状态:syncing  已同步:1.2GB/5.6GB  待同步:321项  错误:0
```

| 字段 | 含义 |
|---|---|
| 连接A | `true` 表示已连接 A |
| A端共享 | `valid` 表示正常。`notSharing` 表示 A 没有把这个文件夹共享给 B，原因是 A 的脚本没运行完，或者两边的文件夹 ID 不同 |
| 状态 | `scanning` 扫描中，`syncing` 同步中，`idle` 空闲，`error` 出错 |
| 已同步 | 已同步的数据量 / 总数据量 |
| 待同步 | 还需要从 A 拉取的文件数 |
| 错误 | 同步失败的文件数 |

- 可以随时按 Ctrl+C 退出，Syncthing 会在后台继续同步。之后在 B 上运行 `sudo bash syncthing-vpc-sync.sh finalize`，会继续等待并切换。
- 在 A 上运行 `status`，看到的"对端完成度"就是 B 的同步进度。
- 如果 A 上的文件一直在频繁变化，可能迟迟等不到"约 30 秒内没有新变化"，切换就会一直推迟。可以挑 A 比较空闲的时候运行 `finalize`。

### B 上已有文件或改过文件

有两类文件会被标记为"本地修改"：开始前 B 的目录里就有的文件，以及首次同步期间在 B 上改过的文件。切换前，脚本会让你选择怎么处理：

```
B 上有 12 项本地修改（B 独有的文件，或在 B 上改动过的文件），切换前需要处理：
  1) 还原：丢弃这些修改，让 B 与 A 完全一致（会删除/覆盖 B 上的这些文件）
  2) 保留：切换为双向后，把这些修改同步给 A（与 A 上同名文件冲突时会生成 .sync-conflict 副本）
  3) 暂不切换，退出
请选择 1/2/3:
```

- **1 还原**：B 变得和 A 完全一致。B 独有的文件会被删除，B 上改过的文件会恢复成 A 的版本。**选之前请确认这些文件已经不需要了。**
- **2 保留**：切换后，这些文件会同步到 A。
- **3 退出**：先自己处理，比如把需要的文件移出同步目录。处理完后运行 `finalize`。

想知道是哪些文件，可以在 B 的 Web 管理界面中点开这个文件夹，查看本地修改的文件列表。

### 手动切换

不用脚本也可以切换。在 B 的 Web 管理界面中编辑这个文件夹，在"高级"（Advanced）里把文件夹类型改为"发送与接收"（Send & Receive）。如果有本地修改，要先决定是否还原（Revert Local Changes）。

## 日常使用

### 查看状态

```bash
sudo bash syncthing-vpc-sync.sh status
```

下面是 B 上正常状态的示例输出：

```
角色          : B（172.16.0.11）    服务 syncthing@root：active
Syncthing     : v2.1.7
本机设备 ID   : XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX-XXXXXXX
监听地址      : 172.16.0.11:22000
对端 A（172.16.0.10）: 已连接（172.16.0.10:22000，v2.1.7）
文件夹        : share -> /data/share
  类型        : sendreceive
  状态        : idle
  本地文件数  : 12345（5.6GB）
  本机待同步  : 0 项，错误 0 项
  对端完成度  : 100%
  冲突文件数  : 0
```

主要看这几项：

- **对端**：应为"已连接"。
- **监听地址**：只有本机私网 IP 的 22000 端口。
- **类型**：A 是 `sendreceive`。B 切换前是 `receiveonly`，切换后是 `sendreceive`。
- **待同步、错误**：空闲时都应为 0。
- **对端完成度**：对方同步到最新的程度，100% 表示已同步完。
- **冲突文件数**：大于 0 时需要人工处理，见下文"冲突文件"。

### Web 管理界面

Web 管理界面只监听服务器本机的 `127.0.0.1:8384`，从外部访问不到。在你自己的电脑上开一个 SSH 隧道：

```bash
ssh -L 8384:127.0.0.1:8384 root@<A 的公网 IP>

# B 没有公网 IP 时，通过 A 跳转。这里本地用 8385 端口，可以和 A 的隧道同时开着
ssh -J root@<A 的公网 IP> -L 8385:127.0.0.1:8384 root@<B 的私网 IP>
```

保持 SSH 连接不断开，在浏览器中打开 http://127.0.0.1:8384 （A），或者 http://127.0.0.1:8385 （B）。

- 端口一般是 8384。如果首次启动时 8384 已被占用，Syncthing 会自动换一个端口，以脚本结束时显示的为准。
- **不要在 Web 管理界面里打开全局发现、本地发现、中继或 NAT 穿透。** 打开后，Syncthing 就不只走私网了。

### 冲突文件

如果两台在同步之前改了同一个文件，Syncthing 会保留修改时间较新的那个版本。另一个版本会被改名保存为：

```
<文件名>.sync-conflict-<日期>-<时间>-<设备 ID 前 7 位>.<扩展名>
```

如果一边删除了文件、另一边修改了它，会保留修改后的文件。冲突副本也会同步到两台。用下面的命令查找冲突文件：

```bash
find /data/share -name '*.sync-conflict-*'
```

对比内容后保留需要的版本，然后删掉冲突副本即可，删除操作也会同步到另一台。

### 旧版本文件（.stversions）

启用版本控制后（默认保留 30 天），本机上因为**对方的修改**而被删除或覆盖的文件，会移到本机同步目录下的 `.stversions` 里。超过保留天数后会自动清理。

- 只保留对方引起的变化。例如在 A 上删除一个文件，A 上不会保留旧版本，B 的 `.stversions` 里会有一份。反过来也一样。
- 每个文件只保留最近一次被替换掉的版本。
- 恢复方法：把文件从 `.stversions` 复制回原来的位置。
- `.stversions` 本身不会被同步。

### 排除不想同步的文件

在同步目录下创建 `.stignore`，每行一条规则：

```
// 这是注释
*.tmp
/cache
```

`.stignore` 本身不会被同步，**两台需要各自创建相同的规则**。也可以在 Web 管理界面的"忽略模式"里编辑。

### 查看日志

```bash
journalctl -u syncthing@<运行用户> -f
```

## 离线安装、指定版本与升级

### 离线安装

脚本默认从 GitHub 下载最新版，并校验 SHA256。服务器访问不了 GitHub 时，按下面的步骤离线安装：

1. 在能上网的电脑上打开 https://github.com/syncthing/syncthing/releases ，下载同一个版本的下面两个文件，**不要改文件名**：
   - `syncthing-linux-amd64-<版本>.tar.gz`（ARM 服务器下载 `arm64` 的）
   - `sha256sum.txt.asc`
2. 把这两个文件放到服务器上脚本所在的目录。
3. 正常运行脚本。脚本会自动找到安装包并校验。如果目录里有多个版本，会使用版本号最高的那个。

也可以用环境变量指定安装包。只有 `sha256sum.txt.asc` 和安装包在同一个目录时，才会做校验：

```bash
sudo env ST_TARBALL=/root/syncthing-linux-amd64-v2.1.7.tar.gz bash syncthing-vpc-sync.sh
```

安装 `jq` 等依赖用的是 apt 软件源，和 GitHub 无关。阿里云的 Ubuntu 镜像默认使用阿里云的内网软件源 `mirrors.cloud.aliyuncs.com`，一般没有公网也能安装。可以在 `/etc/apt/sources.list` 里确认（Ubuntu 24.04 是 `/etc/apt/sources.list.d/ubuntu.sources`）。

### 指定版本

```bash
sudo env ST_VERSION=v2.1.7 bash syncthing-vpc-sync.sh
```

**两台请使用相同的版本。** 连上对方后，脚本会比较两边的版本，不一致时会提示。

### 本机已经装有 Syncthing

如果本机已经有 `syncthing` 命令（例如以前用 `apt install syncthing` 装过），脚本会直接使用它，不重新安装，`ST_VERSION` 和 `ST_TARBALL` 也不会生效。

- 版本要求 v1.12 以上。Ubuntu 软件源里的 syncthing 是比较旧的 1.x 版本，不建议使用。
- 如果是 v1.x，首次启动时会自动创建一个"Default Folder"（`~/Sync`）。它没有共享给任何设备，不影响同步，可以在 Web 管理界面中删掉。
- 想改用脚本安装的版本：先执行 `apt remove syncthing`，再重新运行脚本。

### 升级 Syncthing

脚本关闭了 Syncthing 的自动升级，以免两台版本不一致。需要升级时，在两台上分别执行下面的命令：

- 把 `V` 换成目标版本。
- ARM 服务器把 `amd64` 换成 `arm64`。
- 只能升级，不要降级。

```bash
V=v2.1.8
cd /tmp
curl -fLO https://github.com/syncthing/syncthing/releases/download/$V/syncthing-linux-amd64-$V.tar.gz
curl -fLO https://github.com/syncthing/syncthing/releases/download/$V/sha256sum.txt.asc
grep " syncthing-linux-amd64-$V.tar.gz" sha256sum.txt.asc | sha256sum -c -   # 必须显示 OK 才继续
tar xzf syncthing-linux-amd64-$V.tar.gz
install -m 0755 syncthing-linux-amd64-$V/syncthing /usr/bin/syncthing
systemctl restart syncthing@<运行用户>
```

如果 Syncthing 是用 apt 安装的，上面的方法不适用：先执行 `apt remove syncthing`，再用本脚本安装新版本。

## 重新运行与修改配置

脚本可以重复运行。上次填写的值保存在 `/etc/syncthing-vpc-sync.conf`，再次运行时会作为默认值。下面这些情况可以重新运行：

- 修改 IP、旧文件保留天数或 Web 管理界面密码。
- 设备 ID 或文件夹 ID 填错了。
- 换一个运行用户。脚本会提示停掉旧用户的服务。
- 更改同步目录，见下一节。

注意：

- 重新运行时，会用本次的设置重写对方设备和这个文件夹的配置。你在 Web 管理界面里对它们改过的其他选项会恢复为默认值。`.stignore` 里的忽略规则不受影响。
- 如果 B 已经切换为双向，重新运行后仍然是双向，不会退回"仅接收"。
- 改了文件夹 ID 时，脚本会停止同步上次的文件夹：只移除 Syncthing 里的配置，目录里的文件保留。
- 脚本只管理一个文件夹。要同步多个目录，可以同步它们共同的上级目录，也可以在 Web 管理界面中另外添加文件夹。

## 更改同步目录

先确定是哪种情况：

| 情况 | 例子 | 文件夹 ID | 在哪台运行 |
|---|---|---|---|
| 改为同步另一个目录 | 用测试目录试完后，改为同步正式数据 | 换一个新的 | A、B 都要 |
| 把同一份数据搬到新位置 | 换到新的数据盘 | 不变 | 只在搬的那台 |

> **为什么要区分：** Syncthing 的数据库按文件夹 ID 记录了原目录里有哪些文件。同一个 ID 直接改到另一个目录，Syncthing 发现目录里没有这个文件夹的 `.stfolder`，会报错并停止同步。这时如果手动补上 `.stfolder`，原来的文件会被当成已删除，并把删除同步给对方。所以目录改了、又不是搬移时，脚本会要求换一个新的文件夹 ID。

### 改为同步另一个目录

以把 `/data/test` 改为 `/data/www` 为例：

1. 在 A、B 上同时重新运行脚本：`sudo bash syncthing-vpc-sync.sh`。
2. 目录填新的路径。A 上的新目录必须已经存在；B 上的不存在时，脚本会创建它。
3. 文件夹 ID 填一个新的值，例如 `www`，两台要相同。目录改了时，脚本不接受原来的 ID。
4. 其他问题直接回车，沿用上次的值。对方的设备 ID 没有变，也直接回车。
5. 汇总里会显示"停止同步：上次的文件夹 …"，确认后开始配置。

之后和第一次一样：B 先完整接收 A 新目录里的数据，再切换为双向。

- **旧目录不再同步，里面的文件保留不动。** Syncthing 会删掉其中的 `.stfolder`。旧目录里的 `.stversions` 不会再自动清理，不需要的话可以手动删除。
- **B 上建议用一个新的空目录。** 如果 B 继续用原来的目录，原来的文件会被当成 B 的"本地修改"，切换为双向前脚本会让你选择怎么处理，见"B 上已有文件或改过文件"。想让 B 和 A 的新目录完全一致，就选"1 还原"。
- 一台运行完、另一台还没运行时，先运行完的那台会提示对方"还是上次的文件夹"。等另一台也运行完就好了。

### 把同一份数据搬到新位置

只在要搬的那台上操作，另一台不需要任何操作。以把 `/data/share` 搬到 `/mnt/disk2/share` 为例：

1. 运行 `status`，确认两边已经同步完：待同步 0 项，对端完成度 100%。
2. 停止 Syncthing。搬移期间 Syncthing 不能运行：

   ```bash
   systemctl stop syncthing@<运行用户>
   ```

3. 用 `mv` 把整个目录搬过去：

   ```bash
   mv /data/share /mnt/disk2/share
   ```

   - 目录里的 `.stfolder`、`.stversions`、`.stignore` 会一起搬过去，其中 **`.stfolder` 必须带上**。不要用 `mv /data/share/* …`，因为 `*` 不包括以 `.` 开头的文件。
   - 跨磁盘搬移时，`mv` 会先复制再删除原目录，文件的修改时间和权限都会保留。
   - **是搬移，不是复制。** 如果复制了一份、原目录还留着，脚本会提示"看起来是复制了一份"，要求重新输入。原因是脚本改好路径之前，Syncthing 还会继续使用原目录。这段时间里的变化新目录里没有，改过去后会被当成本机的修改或删除，同步给对方。确实要保留原目录的话，先把它改名。

4. 重新运行脚本，目录填新的位置，文件夹 ID 保持不变，其他问题直接回车。脚本会重新启动 Syncthing。

脚本根据新目录里的 `.stfolder` 确认这是同一个文件夹，汇总里会显示"目录搬移"。搬过去的文件和原来完全一样，不会重新传输。

如果脚本仍然提示"同步目录改了，需要换一个新的文件夹 ID"，说明新目录里没有这个文件夹的 `.stfolder`：

- 忘了带上 `.stfolder`：按 Ctrl+C 退出，把它从原目录搬过来，再重新运行。
- 这个文件夹是 Syncthing v1.28 之前的版本创建的：那时的 `.stfolder` 是空目录，脚本无法确认它属于哪个文件夹。只能按"改为同步另一个目录"处理，换一个新的文件夹 ID。

## 脚本会改动的地方

| 位置 | 内容 |
|---|---|
| `/usr/bin/syncthing` | Syncthing 程序。本机已有 Syncthing 时不安装 |
| `/etc/systemd/system/syncthing@.service` | systemd 服务模板，已有时不覆盖。Ubuntu 22.04 及以上使用 Syncthing 官方的服务文件；Ubuntu 20.04 的 systemd 较旧，使用脚本生成的兼容版本 |
| `syncthing@<运行用户>` 服务 | 启动服务，并设为开机自启 |
| `<运行用户的家目录>/.local/state/syncthing/` | Syncthing 的配置、密钥和数据库。如果已经有旧位置 `~/.config/syncthing/`，就使用旧位置。**设备 ID 由这里的密钥决定** |
| `/etc/syncthing-vpc-sync.conf` | 脚本的状态文件，只有 root 可读。记录角色、IP、对方设备 ID、文件夹 ID、目录等，不含密码 |
| `/etc/sysctl.d/90-syncthing-inotify.conf` | 把 inotify 监控数量上限调到 524288。Syncthing 靠 inotify 实时发现文件变化。原来的上限已经够大时不改 |
| ufw | 启用了 ufw 时，只对对方 IP 放行 TCP 22000 |
| 软件包 | 缺少时用 apt 安装 `curl`、`jq`、`tar` |
| 同步目录 | Syncthing 会在里面创建 `.stfolder`（**不要删除**）；启用版本控制时还会有 `.stversions`。B 上的目录不存在时，脚本会创建它，属主为运行用户 |

## 出问题怎么办

### 连不上对方

等待 90 秒还没连上时，脚本会自动诊断，并给出下面几种提示之一：

| 提示 | 原因和处理 |
|---|---|
| 无法连通 `<IP>:22000` | 安全组或系统防火墙没有放行，或者对方的脚本还没运行完。可以在对方运行 `ss -ltn \| grep 22000`，应该能看到 `<对方私网 IP>:22000` |
| 端口可以连通，但没有建立 Syncthing 连接 | 设备 ID 填错了，或者对方的脚本还没运行完。在填错的那台重新运行脚本，输入正确的 ID |
| 已连接，但对方还没有共享文件夹 | 如果同时提示"对方共享过来的文件夹 ID 是：xxx"，说明两边的文件夹 ID 不同。在填错的那台重新运行脚本，改成和另一台相同的 ID，填错的那个文件夹会被自动移除。如果提示对方"还是上次的文件夹"，说明对方还没有重新运行脚本，见"更改同步目录" |

排查好之后，不需要重新运行脚本（除非要改配置）。Syncthing 会自动重连，用 `status` 确认即可。

### 服务启动失败，或者无法访问 API

查看日志：

```bash
journalctl -u syncthing@<运行用户> -n 50 --no-pager
```

### status 显示有错误

大多是权限问题，也就是运行用户没有权限读写某些文件。在 Web 管理界面中点开这个文件夹，可以看到出错的文件和原因。修正权限后，Syncthing 会自动重试。例如：

```bash
chown -R <运行用户>:<用户组> /data/share
```

### B 一直没有切换为双向

看进度行：

- `连接A:false`：见"连不上对方"。
- `A端共享:notSharing`：A 的脚本还没运行完，或者两边的文件夹 ID 不同。
- `错误` 不为 0：见"status 显示有错误"。
- 一直是 `scanning` 或 `syncing`：数据量大，需要时间。A 上的文件一直在变化时也会推迟，见"什么时候算同步完成"。

### 文件夹报 "folder marker missing"，停止同步

同步目录下的 `.stfolder` 不见了。Syncthing 用这个标记来防止误同步：比如数据盘没挂载、目录变空时，避免把它当成"文件全被删除"同步给另一台。

- 如果是数据盘没挂载：挂载好后重启服务，即 `systemctl restart syncthing@<运行用户>`。
- 如果确实是误删了，而且目录里还是原来同步的那些文件：用运行用户把它创建回来，再重启服务：

```bash
sudo -u <运行用户> mkdir /data/share/.stfolder
systemctl restart syncthing@<运行用户>
```

**目录里已经不是原来那些文件时，不要补建 `.stfolder`**，比如目录被换成了另一个，或者数据没有拷全。补建后，原来的文件会被当成已删除，并把删除同步给对方。这种情况请按"更改同步目录"处理。

### 提示系统时间没有同步

两边改了同一个文件时，Syncthing 按修改时间决定保留哪个版本，系统时间不准会选错。开启时间同步：

```bash
timedatectl set-ntp true
timedatectl          # 确认显示 System clock synchronized: yes
```

如果 `set-ntp` 提示 `NTP not supported`，说明本机用 chrony 同步时间，而不是 Ubuntu 默认的 systemd-timesyncd。这时改为执行 `systemctl enable --now chrony`。

### 提示两端版本不同

把版本较旧的那台升级到相同的版本，见"升级 Syncthing"。

## 卸载

在两台上分别执行。把 `<运行用户>` 等占位符换成实际的值：

```bash
systemctl stop syncthing@<运行用户>
systemctl disable syncthing@<运行用户>

# 脚本安装的程序和服务文件（如果 Syncthing 是用 apt 安装的，改用 apt remove syncthing）
rm -f /usr/bin/syncthing /etc/systemd/system/syncthing@.service
systemctl daemon-reload

# 脚本的状态文件和 inotify 设置
rm -f /etc/syncthing-vpc-sync.conf /etc/sysctl.d/90-syncthing-inotify.conf

# Syncthing 的配置、密钥和数据库（删除后，再次安装时设备 ID 会改变）
rm -rf <运行用户的家目录>/.local/state/syncthing <运行用户的家目录>/.config/syncthing
```

如果启用了 ufw，还要删除放行规则：

```bash
ufw delete allow from <对方私网 IP> to any port 22000 proto tcp
```

最后，如果在安全组里加过 22000 的规则，也一并删掉。

同步目录里的文件不会被删除。如果不再需要，可以手动删掉其中的 `.stfolder` 和 `.stversions`。

## 已知限制

- **这个脚本还没有在真实服务器上完整运行过。** 目前只在一台 Ubuntu 24.04 上用模拟环境测试过，包括以下几部分：
  - 用模拟的 Syncthing API，测试了完整的配置和切换流程、更改同步目录、各种出错提示，以及重复运行。
  - 用本地 HTTP 服务，测试了脚本调用 API 的方式。
  - 用真实的 v2.1.7 安装包，测试了安装包查找和 SHA256 校验。

  **请先用一个测试目录完整走一遍，确认没问题后，再同步正式数据。** 换成正式目录的方法见"更改同步目录"。
- 没有在 Ubuntu 20.04、22.04 上实际运行过。
- Syncthing 首次启动后，到脚本把它改为"只走私网"之前，有几秒钟使用默认配置，期间可能会连接公网的发现服务器和中继。这时还没有添加任何设备和文件夹，不会传输文件数据。
- "首次同步完成"是按上面的条件推断出来的。如果 A 上文件非常多、扫描很慢，可能在 A 扫描完之前就判定为完成并切换。这不会造成数据问题，切换后剩下的文件照常会同步过来。
- 只支持两台服务器、一个文件夹。
- 不同步文件属主：同步过来的文件，属主是运行用户。文件的权限位会同步。
- **Syncthing 不是备份。** 在一台上误删的文件，另一台上也会被删除；如果启用了版本控制，另一台的 `.stversions` 里会留一份。重要数据请另外备份。
